## [0.16.0] - 2026-11-28

### Added

- **Usage forecast**: an island warns when your pace would use up a Claude or Codex rate-limit window, the five-hour one or the weekly one, before it resets. It says when the quota may run out (for example "Claude 5-hour quota may run out around 3:40 PM"), how long before the reset that is, how much is used and how fast. Open it to **Dismiss** it until that window resets or **Snooze** it for an hour. It stays quiet until a window is at least 25% used, 15 minutes old and has three readings, and once shown it stays up for a while (45 minutes for the five-hour window, 6 hours for the weekly one) so a pace near the limit does not make it flicker. Readings are kept between launches. In **Settings › Usage forecast** you turn it off, turn either window off, and set how long before the reset the quota must run out for it to speak. The quota belongs to the account, so other apps signed in to it count too.

### Changed

- **Sessions a conductor starts are listed in Agents.** You can open one and read along; it stays read-only until the conductor lets you work in it.

### Fixed

- A conductor's **Sessions** panel and the banner under its chat stayed empty right after it started a session, until the session's transcript gave it a title. They list it at once now.
- **"Let Lanework read this folder automatically?"** asked again for every new folder of a repository you had already trusted (210 of 216 folders in one real repository). The answer is now kept per repository, because its git settings and hooks are shared by all its folders: a new subfolder or worktree reads without asking. A hook or filter added later still asks, answers you gave before still count, and **Ask again** and **Stop running** in Settings act on the whole repository.
- Pushing a Git LFS repository from the app failed while the same push in a terminal worked, because an app opened from the Dock could not find what git starts by name (`git-lfs`, a hook's `bun`). Every git call now gets your login shell's PATH.
