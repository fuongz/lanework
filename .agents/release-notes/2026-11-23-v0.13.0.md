## [0.13.0] - 2026-11-23

### Added

- **Always allow**: a permission request in a conversation now offers **Always allow…**, which saves a rule for the project. The next matching request is answered without asking and appears under **Recent automatic allows**. Rules apply to Claude, Codex and OpenCode, and to run workers. You manage them in **Settings › Permissions**.
- **Ask first, always**: some actions always ask, whatever you allowed: `git push`, `rm -rf`, piping `curl` or `wget` into a shell, writing outside the project, and answering a session's permission. A command chained with one of them (`git status && rm -rf x`) asks too.
- **Connectors per conductor**: a conductor's new **Connectors** page lists the MCP servers its agent can reach, in tabs for **Claude.ai**, **Plugins** and **MCPs**. Each has a switch, and there is a search and **Disable all**. A conductor only gets the ones you leave on, and the sessions it starts inherit its choice. Press **Refresh** to read your Claude.ai connectors (Gmail, Figma and others).
- **Conductor avatars**: pick an icon, emoji or letter on a colour, the same way as a project's avatar. It shows in the Conductors rail, tabs, chat titles and `@` suggestions.
- **Pin projects**: right-click a project in the project switcher and choose **Pin to top**. Pinned projects always lead the list, above groups and whatever the sort.
- **Idle agents kept running**: **Settings › Power saver** now sets how many idle agents stay running at once (1 to 10, default 3). Past that number, the one unused the longest stops, even with **End idle chats** off. Conductors and chats set to Keep running don't count.

### Changed

- **Context is now part of Memory**: a conductor's **Context** page is now **Files it always reads**, at the top of **Memory**. A new conductor shows the Memory page too, so you can add those files before you save it. Your existing files are kept.
- **Run workers keep to Lanework's servers**: a worker in a run no longer gets your other MCP servers. On a local board, a Claude worker no longer starts them at all.

### Fixed

- Chats no longer seem to stop on their own while **End idle chats** is off: the limit that stopped them is now shown in **Power saver**, and you can change it.
