    Đề xuất hành vi của banner

    • Hiện cho mọi project Local, kể cả người dùng đã thấy repo nhưng chọn không link. Với lựa chọn “không link”, cho ẩn lời mời; vẫn tìm lại được trong Settings.
    • “Để sau” ẩn banner cho project đó trên máy này. Không hiện lại mỗi lần mở app. Settings → Project luôn có “Link repo & đồng bộ”.
    • Bấm CTA → đọc lại origin của tất cả folder → chọn 1 repo → đăng nhập nếu cần → kiểm tra board → xem tóm tắt số card sẽ chuyển → xác nhận.
    • Nếu vẫn chưa có origin: hướng dẫn thêm origin bằng Git hoặc chọn folder khác, kèm “Kiểm tra lại”. Không tự khởi tạo hay sửa repo.
    • Cloud project không hiện banner. Khi offline, hiện trạng thái “Chưa kết nối” riêng; không tự đổi project thành Local.

    Các case cần bổ sung

    Các hướng dưới đây là đề xuất, chưa phải quyết định đã duyệt hay hành vi đã có đủ trong app.

    Trường hợpĐiểm còn thiếuHướng giải quyết đề xuất
    Chưa chọn folder / hủy chooserChưa có gì để kiểm tra hoặc tạo project.Giữ nguyên form, không tạo project. Với luồng này cần ít nhất 1 folder; project không folder là luồng riêng nếu muốn hỗ trợ.
    Local dù đã đăng nhậpNếu mode theo tài khoản, lựa chọn “không link” sẽ không giữ được.Lưu nơi chứa board theo từng project. Một tài khoản có thể mở cả Local và Cloud project.
    Chọn repo nhưng chưa đăng nhập / mất mạngKhông thể hoàn tất tạo cloud board.Giữ folder và repo đã chọn. Cho đăng nhập / thử lại hoặc chủ động đổi sang Local. Không âm thầm tạo một project Local với nhãn Cloud.
    Cùng repo, URL khác nhauSSH, HTTPS, đuôi .git hoặc nhiều clone có thể tạo lựa chọn trùng.Dùng cùng quy tắc chuẩn hóa repo với API. Gộp theo repo chuẩn hóa, giữ các folder nguồn; không gửi URL chứa credential lên cloud.
    Repo đã có boardTạo board mới rồi chuyển link có thể khiến agent của project cũ đổi nơi ghi card.Ưu tiên “Mở board đã có và gắn các folder trên máy”. Với project Local đã có dữ liệu: chưa tự merge; giải thích và giữ dữ liệu Local. Chuyển link / merge cần luồng duyệt riêng.
    Nhiều board / không có quyềnKhông thể quyết định nơi ghi card chỉ bằng tên repo.Không chọn ngầm. Chọn đúng board ID nếu có nhiều kết quả; yêu cầu chủ sở hữu xử lý liên kết nếu API từ chối quyền. Không tiết lộ board mà API không cho thấy.
    Nhiều folder, primary folder khác repo đã chọnBoard gắn repo A nhưng Git/PR có thể đang đọc folder B.Tách “repo của board” và “folder đang thao tác Git”. Mặc định chọn clone của repo đã link làm folder Git ban đầu; các folder khác vẫn hiện trong project. Chat nhận toàn bộ folder và đúng board binding.
    Thêm / bỏ folder, đổi origin sau đóKhông nên tự chuyển board theo cấu hình Git mới.Giữ link board hiện tại. Hiện cảnh báo mismatch và action “Xem lại liên kết”; việc đổi repo là hành động có xác nhận.
    Worktree, subfolder, folder không phải GitGit có thể tìm repo ở thư mục cha; .git có thể là file.Dùng Git để xác định repo root, không chỉ kiểm tra .git là thư mục. Hiện root đã nhận diện. Không tự quét toàn bộ các repo con trong folder.
    Scan chậm / thiếu Git / origin không hỗ trợ“Chưa kiểm tra xong” dễ bị hiểu thành “không có repo”.Có trạng thái đang đọc, timeout và lỗi từng folder. Giữ kết quả đọc được; nêu rõ folder chưa đọc được trước khi tiếp tục. URL không hỗ trợ có thông báo riêng và vẫn cho chọn Local.
    Chat đang chạy khi chuyển boardAgent có thể tiếp tục ghi vào board Local trong lúc dữ liệu chuyển.Chờ các lượt agent đang ghi kết thúc; tạm chặn ghi board trong thời gian cutover. Chỉ lượt chat tiếp theo nhận binding cloud. Không sửa cấu hình MCP global hoặc prompt đang chạy giữa phiên.
    Sync bị gián đoạn / mở app lạiCó thể tạo board trùng, copy thiếu card hoặc ghi cả hai nơi.Lưu migration ID + cloud board ID + mapping card ID, retry vào cùng đích. Chỉ đổi nguồn dữ liệu sau khi kiểm tra hoàn tất; bản Local giữ được để khôi phục nếu chưa cutover.
    Quyền cloud bị thu hồi / sign outDữ liệu cache không đồng nghĩa một local board độc lập.Không tự fork thành Local. Hiện yêu cầu đăng nhập hoặc trạng thái chỉ đọc; xuất một bản Local là thao tác riêng có giải thích.

    Local → Cloud cần một lần chuyển chủ

    Đề xuất chỉ có một nơi nhận ghi tại mỗi thời điểm. “Link repo” và “chuyển board” phải là một luồng có thể tiếp tục nếu bị dừng.

    1 · CHUẨN BỊ

    Đọc lại & xác nhận

    Repo, tài khoản đích, board đích và tổng số card. Kiểm tra quyền, trùng board; chờ agent kết thúc ghi.

    2 · CHUYỂN DỮ LIỆU

    Giữ Local làm nguồn

    Tạm khóa ghi board, lưu migration ID. Gửi config, card, checklist, quan hệ cha/con và checkpoint; retry không nhân đôi.

    3 · XÁC MINH

    Đối chiếu trước khi đổi

    Kiểm đủ dữ liệu và mapping ID. Link repo vào đích sau khi dữ liệu sẵn sàng; lỗi thì giữ Local, cho tiếp tục.

    4 · CUTOVER

    Cloud trở thành nguồn ghi

    Cập nhật project + board binding + lượt chat tiếp theo. Local thành bản lưu chỉ đọc; không có hai board cùng nhận ghi.

    Không thể coi cả luồng là một transaction duy nhất: có SQLite trên máy và API cloud. Cần trạng thái bền vững, điểm tiếp tục và thao tác idempotent. Nếu đã link trên cloud nhưng app dừng trước cutover, mở lại phải hoàn tất đúng migration đó. Không xóa dữ liệu Local khi có lỗi.

    Trạng thái projectNguồn ghi boardMCP trong chat
    LocalLocal SQLite boardLocal project/board ID, qua MCP local của project.
    Đang chuyểnTạm chặn ghi; Local là nguồn đối chiếuKhông mở lượt agent ghi mới; không thay binding giữa một lượt đang chạy.
    CloudCloud board, kể cả khi máy tạm offlineCloud board ID theo project. Kết quả lookup repo là kiểm tra nhất quán, không đoán board theo tên.

    Các folder và đường dẫn vẫn là thông tin của máy. Chọn repo link không đồng nghĩa upload code hay đồng bộ folder lên cloud.

    Bốn điểm em đề xuất chốt

    Đây là các phần cần rõ trước khi triển khai. Các trường hợp 1–4 anh mô tả được giữ nguyên trong sơ đồ phía trên.

    Đề xuất

    Select mặc định là Local

    Kể cả tìm thấy 1 repo, mặc định “Local — chỉ lưu trên máy”. Người dùng chủ động chọn repo để chuyển sang Cloud. Không thêm một nút bật/tắt link song song với Select.

    Đề xuất

    Repo đã có board → dùng lại

    Project mới mở board đã có và gắn folder trên máy. Với Local có dữ liệu, chưa tự merge hay chuyển link: giữ Local, nêu rõ lựa chọn. Merge vào board có sẵn nên là một phạm vi riêng.

    Đề xuất

    Link sau = sync một chiều + cutover

    Giữ task ID, checklist và quan hệ card khi đích là board mới; map ID nội bộ nếu cần. Chỉ đổi sang Cloud khi hoàn tất. Không triển khai đồng bộ hai chiều ở bước này.

    Đề xuất

    MCP gắn theo từng project

    Local và Cloud cùng tồn tại trong một app đã đăng nhập. Chat nhận project ID, board ID, nguồn dữ liệu và repo đã chọn. Không sửa MCP toàn máy khi switch project.

    Khác với luồng BE-20 vừa nối: BE-20 sửa liên kết cho một cloud board đang tồn tại. Luồng mới bắt đầu từ Local hoặc tạo mới project, có thêm lựa chọn nơi lưu và chuyển dữ liệu. Nút Link hiện tại không đủ để thay thế toàn bộ luồng này.

    Phạm vi tài liệu: thiết kế luồng, mô phỏng lựa chọn và đề xuất xử lý thiếu sót; chưa triển khai vào app.

    Đối chiếu source hiện tại: electron/main/projects/sync-to-cloud.ts đã lưu cloudId để retry vào cùng board mới. Luồng “dùng lại board đã có”, ràng buộc origin và cutover MCP cần được rà soát/thiết kế thêm.
